# Shared Definitions

These are present working meanings. “Working” means they may improve through founder narration and operating evidence; it does not mean agents may silently substitute conventional software terminology.

| Term | Working meaning |
|---|---|
| USA LLC | United Stakeholders of America, LLC; founder-controlled Season 1–2 beta operating environment |
| RRCA | Roofing & Reconstruction Contractors of America, LLC; independent operating company and Customer Zero |
| Stakeholder Group | Operating context to which legal entities are assigned and within which roles receive scoped access |
| Legal Entity | Person recognized by law that contracts, owns, owes, employs, receives, pays, licenses, or bears regulated responsibility |
| Company Admin | Human accountable for an entity's users, roles, settings, workflows, evidence, service commitments, and exceptions |
| Super Admin | Scoped high-authority administrator; never implied merely by visibility of navigation |
| Company Agent | Bounded service identity supporting a Company Admin through retrieval, drafting, monitoring, recommendation, and explanation |
| Prospect | Possible participant or opportunity not yet admitted as a Lead |
| Lead | Timestamped opportunity with source and routing history; not automatically a Contact, Customer, or Project |
| Offer | Structured proposal containing work, pricing, exclusions, terms, and supporting evidence |
| Pending Project | Accepted or progressing opportunity awaiting required project execution or activation conditions |
| Project | Executed operating container for Jobs, agreements, evidence, money events, and lifecycle activity |
| Job | Priced scope category within a Project |
| Job Order | Bounded authorization or work unit within a Job |
| Task Request | Expression of a Need for attributable action |
| Task | Assigned action with state, responsibility, evidence, timing, and service expectations |
| Need-to-Done | Universal state trip from identified Need through responsible action and verified completion |
| ClaimExpress | Contracting protocol and SLA translating insurance estimates, Offers, Claim Requests, work, evidence, and financial conditions into standard states and events |
| Claim Request | Insurer response/work request received with time and service commitment; becomes a Need in the workflow |
| Task Efficiency Rating | Proposed quality- and context-adjusted measure of service behavior relative to relevant standards/averages |
| Buddy Claim | Contemplated legal entity/business line serving platform roles and possible attorney-in-fact function for SelfInsurity |
| ClaimBuddy | Independent Contractor platform role; permissions depend on licensing, jurisdiction, assignment, and conflicts |
| SelfInsurity | Envisioned reciprocal/InsurTech concept; not a currently authorized insurer |
| ClaimStore | Proposed neutral transaction, evidence, reconciliation, and potentially regulated market infrastructure |
| Market Applications | Technology-development business line/company concept |
| Human Blockchain | Human-accountable operating model connecting identity, roles, commitments, evidence, work, value, and audit history |
| Quantum Dashboard | Scenario and due-diligence interface for evidence, metrics, assumptions, growth, risk, and valuation ranges |
| Season | Bounded operating and learning period with defined participants, commitments, tests, measures, and review |
| Yearly Reset | Review/renewal of roles, permissions, SLAs, baselines, conflicts, and priorities without erasing history or obligations |
| One Prompt Event | Clean-clone demonstration that a fresh agent team can reconstruct, explain, test, operate, and improve the system from its repository and knowledge bundle |
| Corpus | Historical and current source/derived material used for retrieval, production, validation, acceleration, and evaluation |
| Current working model | Best present expression of Donald's intention; updateable without rewriting source history |
